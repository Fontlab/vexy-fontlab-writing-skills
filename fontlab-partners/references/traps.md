# fontlab-partners traps

Ordered roughly by how much damage getting it wrong does.

1. **Never hand-edit `docs/`.** It is wiped and fully regenerated by `./build.sh build`. Any change made there is lost on the next build.
2. **Never hand-edit `src_docs/_partials/_faq_partial.md`.** It is generated by `./build.sh faq` from `src_docs/faq/`. Edit the FAQ source files, not the partial.
3. **The bottom CTA band is duplicated verbatim in three files with no shared partial** (`src_docs/md/index.md`, `src_docs/md/join.md`, `src_docs/md/downloads.md`). A change to its copy (support contact, commission rate, cookie window) must be applied in all three. Find every copy with `grep -rn "fl-cta-band" src_docs/md/*.md` before editing any one of them.
4. **Support email already drifted between pages.** `src_docs/md/404.md` uses `partners@fontlab.com`; the CTA bands use `partnersupport@fontlab.com`. Do not assume either is the sole correct address; flag the conflict rather than silently picking one.
5. **Cookie-window figure already drifted between a design doc and the live site.** `SPEC.md` cites "180-day cookie"; every live CTA band in `src_docs/md/*.md` says "30-day cookie." Trust the live Markdown, not `SPEC.md`, for any number you quote in new copy.
6. **TransType 4 vs TransType 5.** The site, its filenames, and its asset packs are all keyed to "TransType 4" (`fontlab-marketingpack-transtype-4.zip`, `icon-transtype4-512x512.png`, FAQ commission tables). If the current product is TransType 5, do not silently rename it here. Surface the mismatch, since a rename touches copy, pack name, CSV, and image filenames together.
7. **A new download needs both the Markdown and an asset-whitelist entry, or `--strict-assets` fails the build.** The real whitelist is `src_assets/assets.txt` (pack names) plus one `src_assets/<pack-name>/assets.csv` per pack (one file path per row), not `assets/assets.txt`, as `README.md`'s own prose says in several places. New file in an existing pack: add it to that pack's `assets.csv`. New pack: new `assets.csv` folder plus a new line in `assets.txt`.
8. **Frontmatter differs by content type and nothing validates it.** Sub-pages need `title` (+ usually `description`). FAQ entries need only `question:`. Using the wrong field name does not error; it silently fails to render as intended.
9. **The FAQ category read order is fixed and hardcoded**, not alphabetical: `general → commissions → payouts → tracking → promotion → legal` (`FAQ_CATEGORY_ORDER` in `src/fontlab_partners/cli.py`). A new category needs a code change there, not just a new folder.
10. **`CLAUDE.md`'s architecture section is stale.** It describes a `src_docs/landing/` HTML-assembly pipeline that does not exist on disk. Trust `README.md` for current architecture and build order.
11. **`issues/101.md`, despite being called "the canonical spec" by both README.md and CLAUDE.md, is 39 lines and only covers asset-pack build mechanics.** It is not a content or copy spec.
12. **`SPEC.md` explicitly forbids copy changes** ("No copy changes," under Non-goals). It is a one-time visual redesign brief for the landing page, not a template for writing work.
13. **Never inline the FontLab menu or footer markup.** Load it only via `<script src="https://i.fontlab.com/menu/fontlab.js">`; never paste the component markup directly.
14. **Non-breaking space convention between product name and version** (`FontLab&nbsp;8`, `TransType&nbsp;4`, `Vexy&nbsp;Lines`) is not enforced by tooling and is easy to drop when writing new copy by hand.
15. **The `md/` directory at the repo root is a separate, legacy tree**, not the live source. Live content is under `src_docs/md/`. Do not confuse the two or edit the wrong one.
