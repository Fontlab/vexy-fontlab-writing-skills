    Chinese (Traditional) terms¶

    Portable term table, snapshot of 04 October 2026, generated from the core translation memory localization/zh-hant-core.tmx of the FontLab writing guide by tools/scripts/export_terms.py. 54 of 289 terms are approved or protected; a proposed translation is a candidate for a native reviewer, and the English term is the fallback until it is approved. Use newer supplied project data when it disagrees with this snapshot.

    A status of do-not-translate protects the English spelling; it does not approve a draft English name. The definition says what the term means in FontLab; the note says why the translation was chosen or how to inflect it. The fallback original term is a plain English phrase to translate instead of the term when the term itself will not travel (stem: main stroke; overshoot: optical surplus).

    Type design¶

    English Fallback Chinese (Traditional) Status Note Definition
    ascender upward extension 上伸部 proposed jf 字體口袋書 (justfont), justfont's blog, Glyphs 3 zh-Hant and InDesign zh-TW all use 上伸部; the mainland 上升部 is not used in Taiwan. An ascender is the part of a lowercase letter that extends above the x-height, as in b or d. Ascender height describes the intended alignment of these parts and may differ from cap height. Do not confuse this design measurement with similarly named vertical metrics in exported font tables. Line spacing depends on those fields and on the application using them.
    baseline writing line 基線 proposed Universal: jf 字體口袋書 (justfont), Glyphs 3 zh-Hant, Adobe and Apple zh-TW. A baseline is a reference line used to align text. In conventional horizontal Latin font design, the baseline is at y = 0, with ascenders above it and descenders below it. Other scripts and layout systems can use different baseline conventions. Identify the relevant baseline when discussing alignment across scripts or vertical text.
    bowl round belly 字碗 proposed jf 字體口袋書 (justfont) lists bowl as 字碗; Apple's shape name 碗 is the wrong sense. A bowl is a rounded stroke that encloses a counter, as in b, d or p. Its shape, thickness and junctions affect the letter's balance. The appropriate number of curve segments depends on the design. Nodes at extrema can help editing and hinting, but a fixed segment count does not guarantee compatible masters or good interpolation.
    cap height capital-letter height 大寫字高 proposed jf 字體口袋書 (justfont), justfont's blog and Glyphs 3 zh-Hant use 大寫字高. Cap height is the distance from the baseline to the top of a flat capital such as H. Rounded or pointed capitals may extend beyond it through overshoot. Record the intended value in Font Info. Cap height describes a design measurement; alignment zones and line-spacing metrics are separate settings, even when their values are related.
    character 字元 proposed Universal in Taiwan (Apple, Adobe, Microsoft, justfont); kept distinct from 字符, the glyph. The mainland uses 字符 for character, so the two catalogs must not be converted mechanically. A character is an abstract unit of written text, such as a letter or punctuation mark. A glyph is its visual representation. The relationship is not one to one: several characters can form a ligature, and a character can have several glyph forms. A user-perceived character can also consist of several Unicode codepoints. Keep characters, codepoints and glyphs distinct when discussing encoding or text processing.
    contour 輪廓 proposed FontForge zh_TW uses 輪廓 for one contour (命名輪廓, 關閉開放輪廓); Glyphs 3 zh-Hant says 路徑 and 外框. Unlike Simplified, Taiwan usage lets contour (輪廓) and outline (外框) keep separate words. A contour is an open or closed sequence of connected line and curve segments. Its nodes and control points describe its geometry. One glyph or vector object can contain several contours. A counter is an area of space, not a synonym for a contour. When explaining fill behaviour, identify the outline format and fill rule before prescribing a contour direction.
    counter enclosed white space 字腔 proposed jf 字體口袋書 (justfont) and justfont's blog use 字腔 for counter, closed or open; 字懷 is their word for the Hanzi concept and 計數器 is the office-suite sense. A counter is the enclosed or partly enclosed space within a letterform, such as the enclosed space in an o or the open space in a c. The surrounding strokes define it. A closed counter may have an inner contour as its boundary; an open counter does not require a separate contour. Judge its size and shape together with the surrounding strokes.
    descender downward extension 下伸部 proposed jf 字體口袋書 (justfont), justfont's blog, Glyphs 3 zh-Hant and InDesign zh-TW all use 下伸部. A descender is the part of a letter that extends below the baseline, as in p or y. Its design height is usually recorded as a negative coordinate relative to the baseline. Exported descender metrics are separate fields used by applications for layout. Whether a deep glyph clips depends on the relevant metrics, application and text container, not on one design value alone.
    diacritical mark combining mark 變音符號 proposed Yin Tzu-Yuan's zh-TW Glyphs scripts and Apple zh-TW use 變音符號; 附加符號 is the alternative. A diacritical mark is a small sign, such as an acute or a cedilla, that attaches to a base letter to form another character. FontLab builds accented glyphs from a base and a mark through anchors, and the GDEF mark class tells the shaper which glyphs are marks. Say mark glyph for the class member and diacritical mark for the sign.
    em type body 字身框 proposed jf 字體口袋書 (justfont) calls the design square 字身框; same concept as the Simplified decision. justfont's blog and FontForge zh_TW leave em in Latin script for the unit, which is the alternative. The em is the square on which a typeface is designed, historically the body of the letter M in metal type. Its height equals the type size, so an em in 12 point text is 12 points. In a digital font the em is divided into UPM font units.
    extremum local extreme point 極值點 proposed Mathematical term, shared with the Simplified decision; FontForge zh_TW's 末端 is a mistranslation. No Taiwan type source found, so check with a reviewer whether 極點 is preferred. An extremum is a point where a curve reaches a local leftmost, rightmost, topmost or bottommost position. The plural is extrema. Placing nodes at extrema can help editing and hinting. If you add nodes to masters intended for interpolation, preserve the correspondence between their contours and points. Different extremum positions alone do not make masters incompatible.
    glyph 字符 proposed jf 字體口袋書 (justfont) (字符 Glyph), Glyphs 3 zh-Hant and InDesign zh-TW use 字符; Apple zh-TW's 字形 is justfont's word for letterform and FontForge zh_TW's 字圖 is isolated. Departs from the Simplified 字形 on regional evidence. A glyph is one drawn shape in a font: a letter, a figure, a mark, or a piece of a composite. A character is what a reader types and a glyph is what a renderer draws, and one character can map to several glyphs while several characters can map to one. You edit a glyph in the Glyph window, where its contours, elements, anchors, and metrics all live together. The distinction matters in any sentence about encoding, since a font maps codepoints to glyphs through the cmap table.
    handle 控制桿 proposed Yin Tzu-Yuan's Glyphs 101 tutorials and Blender zh_HANT use 控制桿; Adobe zh-TW's 控制把手 and 方向控制點 are the alternatives, and 控制代碼 is the programming sense. A handle is an off-curve control point used to shape a curve segment. A cubic Bézier segment has two control points; a quadratic segment has one. Moving a handle changes the curve without moving its endpoints. In tools that display handle arms, the arm connects a control point to an endpoint. Name the curve type when the number or behaviour of handles matters.
    ink trap ink relief notch 墨溝 proposed justfont's blog glosses ink trap as 墨溝; 油墨陷阱 is the literal mainland rendering. An ink trap is a notch cut into a corner where strokes meet, so ink spread or rasterization at small sizes does not clog the join. FontLab makes them as a live Smart Corner variant.
    italic angle slant angle 斜體角度 proposed FontForge zh_TW uses 斜體角度 and 斜體 is the Apple, Adobe and Microsoft zh-TW word for italic; Glyphs 3 zh-Hant's 義大利體斜角 is the alternative. The italic angle is the slope of the upright strokes of an italic or oblique design, measured from the vertical in degrees. FontLab stores it in Font Info, uses it to slant guides and the cursor, and writes it into the post and hhea tables. It is a property of the design, not of a transformation.
    lining figures capital-height figures 等高數字 proposed jf 字體口袋書 (justfont) uses 等高數字; Glyphs 3 zh-Hant's 齊高數字 and InDesign's 齊線 are the alternatives. Lining figures are digits that share the cap height and sit on the baseline, so they align with capitals in tables and headlines. The lnum feature selects them where a font defaults to oldstyle figures.
    node 節點 proposed Yin Tzu-Yuan's Glyphs 101 and Inkscape zh_TW use 節點; Glyphs 3 zh-Hant's 控制點 rejected because it must name the off-curve control point. A node is a point on a contour where segments meet, and its type decides how they meet. A sharp node lets two segments arrive at any angle. A smooth node keeps the handles collinear so the curve passes through without a kink. A tangent node joins a line to a curve smoothly. A G2 node matches curvature as well as direction. You select a node and drag it, or nudge it, and the segments on both sides follow. Put nodes at the extremes so hinting and interpolation have something to hold.
    overshoot optical surplus 出框微調整 proposed jf 字體口袋書 (justfont), justfont's blog (出框微調整, overshoot) and Yin Tzu-Yuan use 出框微調整; Blender's 過衝 is the engineering sense. Overshoot is the extension of a rounded or pointed shape beyond an alignment line so that it appears as tall as a flat shape. For example, an o may extend above the x-height and below the baseline. Its amount depends on the design and intended size. PostScript alignment zones can describe these overshoot regions for hinting; there is no universal percentage to apply.
    proportional figures natural-width figures 比例寬數字 proposed Glyphs 3 zh-Hant uses 比例寬數字; InDesign's 等比 rejected. Proportional figures have individual advance widths, so a 1 takes less room than an 8. They read well in running text; tabular figures share one width for columns. The pnum feature selects them.
    segment 線段 proposed Glyphs 3 zh-Hant, Yin Tzu-Yuan and Inkscape zh_TW use 線段. A segment is the portion of a contour between two on-curve endpoints. It may be a straight line or a curve. A quadratic Bézier segment has one off-curve control point; a cubic segment has two. Describe the segment type and the relevant editing command rather than assuming that every curve has two handles or that changing a node type performs every conversion.
    serif 襯線 proposed jf 字體口袋書 (justfont) and FontForge zh_TW use 襯線 for the serif itself; 襯線體 names the typeface class. A serif is the finishing stroke at the end of a stem or arm. Its shape sorts a face into the familiar classes: oldstyle, transitional, Didone, slab. You draw a serif once and reuse it as a component or an element, which keeps a family consistent and makes a late change cheap. Serifs are small, so they take the most damage at low resolution, which is where hinting and careful alignment zones earn their place.
    sharp 尖角 proposed Adobe zh-TW uses 尖角 for a pointed corner; 銳利 and 銳利化 are image-sharpening words. Sharp describes a pointed corner or a node at which contour direction can change abruptly. Image sharpening is a different operation.
    sharp node 尖角節點 proposed Built from 尖角 and 節點. A sharp node joins contour segments without requiring a smooth change of direction. The handles of adjacent segments need not be collinear; a smooth node constrains their direction.
    stem main stroke 字幹 proposed jf 字體口袋書 (justfont), Glyphs 3 zh-Hant and FontForge zh_TW use 字幹. A stem is a main stroke of a letter, usually the vertical one: the two uprights of an H, the single upright of an l. Stem width sets the weight of a face, and stems that disagree across a family break its rhythm. You measure a stem with the Measurement tool and record the standard widths in Font Info, where hinting and the stem links read them. Vextra reuses the word for the paired edges it detects in general artwork, not only in letters.
    swash flourish 花飾字 proposed Glyphs 3 zh-Hant, Apple CoreText and InDesign zh-TW use 花飾字. A swash is a decorative flourish that extends a letter, often on a capital or a terminal. Swash alternates live in the swsh feature and in glyphs with a swash suffix.
    terminal stroke ending 末端 proposed jf 字體口袋書 (justfont) describes serifs as sitting at the 筆畫末端; its anatomy table gives 端點 for terminal, which is rejected here only because 端點 is the stroke cap. 終端機 is the computer terminal. A terminal is the end of a stroke without a serif, such as the ending of a c or f. Its shape may be rounded, angled or cut off, depending on the design. Compare related terminals across a typeface at the intended reading size. The anatomical term does not prescribe how to construct or store the shape in an editor.
    UPM units per type body UPM proposed Glyphs 3 zh-Hant keeps the acronym (變更 UPM, 調整至UPM); spell out as 每字身框單位數 in prose. Keep numeric controls compact: LSB/RSB (French AG/AD), UPM and PPM. Expanded terms belong in explanatory help; the full Family Dimensions Units Per eM label is an intentional exception. Team UI convention in Proteus 1751b28b0. UPM, units per em, specifies how many font units make up one em. It sets the scale for outline coordinates and metrics when a renderer converts them to a text size. Values such as 1000 and 2048 are common; TrueType outlines do not require a power of two. When changing UPM, distinguish changing the scale value from rescaling the outlines and metrics.
    winding direction drawing direction 輪廓方向 proposed Fallback drawing direction translated with 輪廓; Glyphs 3 zh-Hant says 外框方向 and Adobe 路徑方向. Winding direction is the order in which a contour runs, clockwise or counter-clockwise, and it decides which areas the renderer fills. FontLab follows the PostScript convention: outer contours wind counter-clockwise and counters wind clockwise. The letter O is two contours, one each way. You check direction before you export, and reverse a contour when a counter fills solid or an outer shape turns hollow. A renderer applies the rule at draw time, so the error shows in the proof rather than in the editor.
    x-height small-letter height x 字高 proposed jf 字體口袋書 (justfont), justfont's blog and Glyphs 3 zh-Hant use x 字高; FontForge zh_TW's 小寫字母高度 rejected. The x-height is the height of a lowercase x above the baseline, and it stands for the height of the lowercase in general. It does more for apparent size than the point size does: two faces at the same size look different when their x-heights differ. You record it in Font Info so hinting and alignment zones can use it, and you draw round letters slightly above it to allow for overshoot. Write it lowercase with a hyphen, even at the start of a sentence recast to avoid one.

    Font engineering¶

    English Fallback Chinese (Traditional) Status Note Definition
    advance height 直排字高 proposed Vertical counterpart of 字寬; Glyphs 3 zh-Hant has 垂直字高 and 垂直高度 for Vertical Width and uses 直排 for vertical setting. FontForge zh_TW's 垂直前加 rejected. The distance the text position advances vertically after a glyph. It is the vertical counterpart of advance width, not the height of the visible outline.
    advance width glyph box width 字寬 proposed Glyphs 3 zh-Hant uses 字寬 for the glyph's advance (設定字寬, 左邊界+字寬); justfont's blog spells it out as 步進寬度, the form for explanatory prose. FontForge zh_TW's 前加寬度 rejected. Advance width is the horizontal distance allocated to a glyph before layout adjustments, measured in font units. In an OpenType font, the base values are stored in the hmtx table. Kerning and other positioning operations can adjust advances during layout without rewriting those base values. Advance width differs from the visible outline width; a space can have an advance without an outline.
    alignment zone height band for snapping 對齊區域 proposed Glyphs 3 zh-Hant and Yin Tzu-Yuan's zh-TW Glyphs scripts use 對齊區域. An alignment zone is a region around a common vertical alignment, such as the baseline or cap height, used in PostScript hinting. It can include the overshoot of rounded letters. A rasterizer uses zone information when fitting outlines to a pixel grid. Keep this mechanism distinct from design measurements and from the control-value and instruction mechanisms used in TrueType hinting.
    anchor attachment point 錨點 proposed Glyphs 3 zh-Hant, FontForge zh_TW and Yin Tzu-Yuan's tutorials all use 錨點. An anchor is a named attachment point in a glyph that says where a mark belongs. A base letter carries a top anchor, and the accent carries a matching one, so the accent lands in the same relation on every letter that uses it. You place anchors in the Anchors and Pins panel, and FontLab uses them both to build composites and to generate mark attachment lookups in GPOS, which is what positions marks in text the font never composed itself.
    anti-aliasing edge smoothing 消除鋸齒 proposed FontForge zh_TW uses 消除鋸齒, the usual Adobe zh-TW wording; Krita's 反鋸齒 and 抗鋸齒 are the alternatives. Anti-aliasing paints partly covered pixels in intermediate shades so a rendered outline looks smooth. FontLab's preview can show anti-aliased, monochrome or subpixel rendering so you can check how hints behave under each. Write the hyphenated form.
    autohinting automatic screen fitting 自動 Hinting proposed Built from 自動 and the retained loan Hinting; justfont's blog also leaves hinting in English. Autohinting generates hints for a font from its outlines and its declared stems and zones, in one pass over the glyphs. It is a starting point rather than a finish: it hints the regular cases well and leaves the awkward glyphs for you. You run it after the alignment zones and standard stem widths are correct in Font Info, because it reads them. Then you check the glyphs that matter at text sizes and correct by hand what the pass got wrong.
    axis 變化軸 proposed jf 字體口袋書 (justfont), Glyphs 3 zh-Hant and Yin Tzu-Yuan all call a variation axis 變化軸; bare 軸 is kept for compounds (字重軸). FontForge zh_TW's 軸線 and Microsoft's 座標軸 rejected. An axis is one dimension of font variation, such as weight, width or optical size. In an OpenType variable font, each axis has a four-character tag and a minimum, default and maximum value. Registered tags, such as wght, have defined meanings. Preserve tag spelling and case, and check the axis registry when assigning a custom tag.
    axis map axis value mapping 變化軸對應 proposed Glyphs 3 zh-Hant renders Axis Mappings as 變化軸對應. An axis map converts user coordinates on an axis, such as weight 400, to the design coordinates of the masters. It is stored in the avar table and lets a slider feel even when masters are not.
    bottom sidebearing 下留白 proposed Derived from 留白; FontForge zh_TW has 底留白 for BBearing. The space below the glyph outline within its vertical advance. This value participates in vertical text spacing rather than horizontal spacing.
    component 組件 proposed Glyphs 3 zh-Hant and Yin Tzu-Yuan use 組件; 元件, the general software word (Adobe, Microsoft), rejected to keep component apart from element. A component is a reference to another glyph placed inside this one, so that aacute holds the a and the acute rather than copies of their outlines. Change the source glyph and every glyph that references it follows. You build composites from components, position them with anchors, and keep them as references through to export, where a TrueType flavoured font stores them in the glyf table. In FontLab a component is one kind of element reference.
    composite glyph assembled glyph 組合字符 proposed Yin Tzu-Yuan's zh-TW Glyphs scripts say 組合字符 and FontForge zh_TW 組合字圖; the Simplified 复合 has no Taiwan attestation. Contextual alternates, the calt feature, cover substitutions an app makes because of what sits around a glyph rather than because a reader asked. In a script face the text engine replaces an entry stroke after a letter that already ends in one, and in a face with repeating shapes it replaces the second of a pair. You write the rules with context in feature code, and apps usually leave calt on by default, which makes it the feature most likely to surprise you when a rule is too broad.

Cursive attachment joins glyphs by matching an exit anchor of one glyph to the entry anchor of the next, so connected scripts such as Arabic and Nastaliq flow. It is the curs feature, built from anchors.

You edit it in the Features panel, compile it to check for errors, and keep it under the same review as the drawings, since a rule that fires on the wrong glyph is as visible as a wrong outline. FontLab compiles it into GSUB and GPOS at export.

In OpenType, the frac feature supports diagonal fraction composition through glyph substitution. A font may provide precomposed fraction glyphs, numerator and denominator forms, or both. The separate numr and dnom features provide numerator and denominator forms. Do not substitute the sups and subs feature names for these mechanisms or promise support for every input sequence without testing it.

A glyph index is the number a glyph occupies in the font's own order, counting from zero. Text engines work in indices after the cmap has done its job, and binary tables reference glyphs by index rather than by name. You rarely set one by hand, but you meet it when you inspect a compiled font or debug a lookup that fires on the wrong glyph. The index depends on glyph order, so it changes when the order does.

Names such as a, a.sc and a.alt can distinguish related drawings. They are separate from Unicode assignments and glyph indices, and need not survive in every exported format. After renaming a glyph, check references in feature code, classes and scripts, including references the editor cannot update automatically.
    GPOS GPOS do-not-translate GPOS is the OpenType table that holds positioning: kerning, mark attachment, cursive attachment, and any rule that moves a glyph without replacing it. FontLab writes your kerning here, as pairs and as class based positioning, and builds the mark lookups from your anchors. You reach it through feature code rather than by editing the table. A font may also carry a legacy kern table; modern text engines read GPOS and many ignore the other.
    GSUB GSUB do-not-translate GSUB is the OpenType table containing glyph-substitution lookups. It supports operations such as replacing a glyph with an alternate, forming a ligature or selecting a form from its context. FontLab compiles feature code into these structures. To diagnose a missing substitution, check the glyphs, compiled rules, feature selection, language and shaping order in the target application.

The liga and dlig features distinguish standard and discretionary ligatures. Shaping does not change the underlying text; whether a later document export preserves searchable text also depends on that export and its text mappings.

The OpenType locl feature can provide these substitutions, for example Bulgarian forms of Cyrillic letters. The shaping engine needs the relevant language information, which the application may obtain from a setting or other context. The substitution changes glyph selection, not the underlying characters or their codepoints.

It differs from FontLab's nonspacing element, which is a property of an element inside a glyph.

Figure height and figure width are separate choices: oldstyle figures can be proportional or tabular. Use tabular widths when numerals must align in columns, whether their forms are oldstyle or lining.
    OpenType class layout glyph group OpenType 類別 proposed Glyphs 3 zh-Hant and FontForge zh_TW use 類別 for classes; name protected. An OpenType class is a named group of glyphs that feature code can address at once, written with an at sign before the name. One rule over two classes replaces a page of single rules, and one edit to a class reaches every rule that cites it. You define classes in the Classes panel or in feature code, and you keep their order stable, because a substitution between two classes pairs them by position. Kerning classes are a separate mechanism with the same idea.

An OpenType feature identifies typographic behaviour through a four-character tag, such as liga, smcp or ss01. Feature records reference substitution or positioning lookups. In FontLab, you can write feature code and compile it into the font. Whether and when a feature is applied depends on the shaping engine, script, language and application settings; not every feature is a user-controlled switch.

The OS/2 table carries the font's metadata for applications: vertical metrics, weight and width classes, embedding permissions, the panose values, and the codepage and Unicode range bits that say what the font covers. You fill it from Font Info rather than by hand, and you check it before release, because a wrong weight class puts a font in the wrong slot in a menu and wrong vertical metrics change line spacing in every browser. Write it with the slash: OS/2.
    Private Use Area Private Use Area do-not-translate A private-use area is one of three Unicode blocks whose codepoints can receive meanings by private agreement. Different fonts or systems may assign different meanings to the same private-use codepoint. Use a documented agreement when encoding custom symbols there. An alternate glyph reached through a feature does not require its own private-use assignment.
    single substitution 單一替換 proposed FontForge zh_TW has 單一替代; 替換 is used instead (Glyphs 3 zh-Hant: 以替換方式) so that substitution stays apart from 替代, the word for alternates. A single substitution replaces one glyph with one other glyph, the simplest GSUB lookup type. Small caps, stylistic alternates and localized forms are mostly built from it.
    small caps small capitals 小型大寫字母 proposed jf 字體口袋書 (justfont) and FontForge zh_TW use 小型大寫字母; Glyphs 3 zh-Hant's 小字大寫 and InDesign's 小型大寫字 are the alternatives. Apps apply the smcp feature to put them in place of lowercase letters, and c2sc to put them in place of capitals, so a run set in both features becomes uniform. You draw them as separate glyphs, usually with a dot sc suffix, and write both features. Scaled capitals look thin beside real text, which is the reason to draw them rather than let an app fake them.

A stylistic set is a numbered group of alternate glyphs a reader can switch on, from ss01 through ss20. Each set holds alternates that belong together: a single storey a with a matching g, a set of flat topped figures. You name each set in the font so an app can show a readable label instead of a number, and you keep one idea per set. A set that mixes unrelated alternates gives a reader nothing they can decide about.
    tabular figures equal-width figures 等寬數字 proposed Built from 等寬 (jf 字體口袋書 (justfont)); Glyphs 3 zh-Hant's 等寬齊高 names tabular lining only and FontForge zh_TW has 定寬數字. They matter in any table, price list, or running total, and they look loose in prose, which is why a font offers both sets rather than choosing for the reader.
    Unicode codepoint character code Unicode 碼位 proposed 碼位 is the Chinese Unicode term for a code point, shared with the Simplified decision; not attested in the corpus. A variation selector is a Unicode character that follows a base character to request a specific glyph form. The pair is a variation sequence, mapped in the cmap format 14 subtable; a default mapping points at the base glyph.
    writing system 書寫系統 proposed W3C's Chinese layout requirements use 書寫系統; Microsoft zh-TW's 文字系統 is the alternative, and Glyphs' 語系 and Apple's 文字 name the OpenType script. Say writing system in prose and script tag for the identifier, so the reader does not confuse it with a Python script.

A tonal map is the reading of brightness across a source image that a fill uses to decide where to put geometry. Dark areas widen a strip or crowd a pattern; light areas narrow or thin it. You control the mapping with the Brightness, Contrast, and Source Levels rows, which change what counts as dark before any geometry is drawn. Adjust the map rather than the fill when the result is uniformly too heavy or too sparse.
